wince.hhk launcher, Luna design v1

The fx-CP400 screen at its real 320×528 resolution, drawn only with what the HHK stub can do on its own: row-gradient fills, rounded rectangles and a bitmap font. Pick an action with ▲ ▼ and press EXE to watch the flash run.

What changed from the text launcher

  • Four named actions instead of one EXE prompt. Each one says what it writes and whether it survives: Persistent (NK.bin in the NOR window) or Non-persistent (EXT.bin, cleared the next time Casio OS starts).
  • Actions that need a missing file are greyed out and say which file is missing, so the user never presses EXE on something that cannot run.
  • The status box answers "will this rewrite my flash?" before anything happens: what the window holds and whether NK.bin differs.
  • Flashing shows the step list, a bar for the current step and a bar for the whole job, with bytes and time left. Cancel is disabled while sectors are being written.
  • The start screen is on black, laid out like the CE 5.0 header art: the XP flag left of the original lettering (white on black, original resolution), then the marquee, which freezes at takeover.

Porting to dbt/hhk

  • Built as a gint program (dbt/hhk/loader.c): drawing goes into gint's VRAM (RGB565, 320×528) and dupdate pushes it; keys, clock and files are gint's, with no OS addresses. During flashing only the step list and the progress box are redrawn.
  • Gradients are per-row colour tables (title bar 28 rows, progress chunks 12 rows), so a fill is one store per pixel with no maths.
  • All text is 1-bit (no antialiasing), as it will be on the device. It comes from embedded bitmap fonts (hinted Tahoma and Trebuchet MS, tools/mkbitmapfont.py); the flag ships as prescaled RGB565 bitmaps (17×15 title icon and the 36 px flag and the 171×32 lettering from tools/mkbootlogo.py).
  • Progress comes from nkflash.c's nk_progress hook: per erased sector, per record, and every 64 KiB written or compared.
